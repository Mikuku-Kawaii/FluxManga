FluxManga modifications:
- Protocol constants, signed paths, login, list/metadata mappings and chapter/page
  pagination adapted to the existing Kotlin Repository and Rust reqwest session.
- Token is sealed in the private world's existing storage. Source identity binds
  to users/profile UID. Password is not persisted; account switching retains books.
- Chapter pages are collected sequentially and sorted by server order; only the
  selected chapter's image references are collected. UI pagination remains explicit.
- Anonymous image requests use the existing encrypted private image pipeline and
  Android bounded region decoding; API authorization is not sent to image hosts.
- No Mihon extension host, Go runtime, global account, new database, DNS routing,
  HTTP address bootstrap, automatic login/check-in or remote favorite writes.

HmacSHA256.kt was inspected as protocol evidence and credits
https://github.com/czp3009/picacomic-api in its header. Its helper/hex-table code is
not copied into FluxManga. This adapter calls standard Android JCA HmacSHA256 and
uses the project's existing hexadecimal formatting idiom.

Complete primary Apache-2.0 and supplemental MIT texts are retained together in
picacg-LICENSES.txt. Upstream source samples and provenance are retained under
docs/verification/m4-storage-foundation-local/picacg-upstream and indexed in
docs/third-party/source-adapters.json. This adaptation has not been compiled,
tested, packaged or exercised against real accounts/services in this stage.

2026-11-11 automatic re-login follow-up (supersedes the original no-password /
no-automatic-login limitation above): reuses the same pinned MIT pica-go
client.go Login and dto.go LoginRequest (email/password -> auth/sign-in).
No Go runtime or new dependency. Explicit setup verifies users/profile UID,
then stores credentials in the existing private-world encrypted session.
A WorldSession owner merges expired-token reads, validates the same UID,
renews the token and replays each read once. Login itself is not replayed or
redirected to a fallback host; HTTP 403 and image failures do not trigger login.
Cooldown, cancellation and manual connection identity protect account changes;
logout removes saved credentials while preserving books and reading progress.
Implementation/source review only; no compilation, tests or device deployment.
